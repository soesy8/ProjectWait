# Wait_Robby

`Assets/M/Scene/Wait_Robby.unity`는 세 가지 상황을 고르는 작은 체험 광장이다. 기존 `Wait_Title`에서 이름만 변경했으며 GUID를 유지한다.

- 왼쪽: 회색 문 두 기, 중앙 호출판, 3F 표시가 있는 엘리베이터 로비.
- 정면: 앞이 열린 정전 사무실. 조명과 구형 모니터 화면은 꺼져 있다.
- 오른쪽: 산호색 자동차, 보행자 신호등, 횡단보도로 구성한 짧은 도로.

세 구역의 앞면은 플레이어 시작 위치를 바라본다. 엘리베이터와 횡단보도를 좌우 안쪽으로 돌려 플레이어를 둘러싸는 배치로 구성했다. 사용자가 넓혀 둔 구역 간격과 회전은 유지한다. 공통 바닥과 바닥 콜라이더는 가로 18m, 깊이 10m로 확장했으며, 가장자리 화단도 함께 옮겼다. 실제 이동 영역은 기존 가로 9.6m, 깊이 3.8m를 유지한다.

각 구역의 앞쪽 아래에는 사용자가 낮춰 둔 높이 0.38m의 전시 설명 패널이 있다. 상단 간판과 기존 선택판의 기둥·받침은 제거했으며, 패널 면만 X축으로 35도 기울였다. 기존 `DialogueFrame`, `ButtonTeal`, `ButtonCream` UI 아트를 사용하고 한글 제목·간단한 설명·체험 시작 버튼으로 구성했다. 멀리 있는 패널은 가까이 이동한 뒤 선택한다. 횡단보도의 자동차는 수직 Y축을 기준으로 기존 방향에서 180도 회전했고, 사무실은 `CRT screen OFF` 검은 덧패널만 제거해 모니터 본체·받침·책상을 보존했다.

가독성 조정: 패널을 1.50×0.86m에서 1.28×0.78m로 축소했다. Canvas의 월드 스케일은 그대로 두고 제목 56→72, 설명 30→40, 버튼 글자 34→44로 키웠다. 버튼은 414×74에서 464×86 UI 단위로 확장했다. 실제 글자와 버튼도 커지며, 배경·뒷면·패널 콜라이더는 줄어든 패널 크기에 맞춘다. 기존 위치·낮춘 높이·35도 기울기·문구·클릭 연결은 유지한다.

## 조작과 연결

- PC: WASD 이동, 마우스 둘러보기, 중앙 점으로 패널을 가리킨 뒤 왼쪽 클릭. Esc로 커서를 풀거나 다시 고정한다.
- 실제 XR 장치가 활성화되면 머리 추적, 왼손 스틱 이동, 오른손 스틱 30도 회전, 오른손 트리거 선택을 사용한다. Mock HMD에서는 PC 조작을 유지한다.
- 엘리베이터 패널은 기존 `Wait_Elevator` 씬을 연다.
- 정전·횡단보도는 이번 작업에서 전시 공간만 구현했다. 패널을 누르면 준비 중 안내를 표시한다. 추후 각 `TitlePortal.destinationScene`에 대상 씬 경로를 연결한다.

## K 키 구 전용 페이드와 물방울 효과음

씬 루트의 빈 오브젝트 `LobbyDissolveTest`가 로비만 제어한다. Play 후 **Game 뷰를 클릭하고 K**를 누르면 먼 표면부터 가까운 표면 순으로 사라진다. 완료 후 다시 K를 누르면 가까운 곳부터 나타난다. 재생 도중의 K 입력은 무시한다. Inspector 컴포넌트의 컨텍스트 메뉴 `Toggle fade (Play Mode)`로도 실행할 수 있다. 게임 시작 시 자동 재생하지 않는다. 아래 이야기 씬 전환에서는 같은 렌더러/팝 사운드를 임시로 빌려 쓰며, 그동안 K 입력은 받지 않는다.

- **저사양 구 전용으로 고정**했다. 연결 목·정밀 메타볼·평면 점무늬 비교 모드 및 품질 전환 체크박스는 제거했다. 승인된 구 전용의 색·3단계 명암·갈색 외곽선·반지름 곡선·그림자 설정을 유지한다. 실제 유체 물리나 메타볼 합집합 계산은 없다.
- 기본값: 사라짐/나타남 각각 `3초`, 경계 폭 `3m`, `Droplet Spacing = 0.36m`, `Droplet Radius = 0.43`, `Maximum Droplets = 1800`. 상한에 따라 간격을 넓히고 최소 간격을 유지한다. 시작점의 932개 표본·실제 간격 약 `0.523m`는 이전과 같다. 기존 직렬화 값은 `FormerlySerializedAs`로 이관했다.
- 구마다 GameObject를 만들지 않고 **고정 메시·렌더러·물방울 재질 하나**를 공유한다. 12방향·8위도의 닫힌 구와 역방향 외곽선 메시를 합친다. 재생 중에는 셰이더 진행률만 갱신하고, 표면 추출·작업 스레드·정점 업로드가 없다. 메시는 표본이 바뀔 때만 다시 준비한다. 반지름 최대값까지의 보수적 bounds를 사용하며 반지름 변경만으로는 메시를 재생성하지 않는다.
- 정점은 외곽선 포함 `160,304`, 삼각형은 `313,152`다. 남아 있던 품질 분기와 파트너 데이터도 정리해 정점당 데이터가 저품질 비교 버전의 `56 → 48바이트`로 줄었다. 매 프레임 표본 전체를 훑던 진단 계산을 조회 시점으로 옮겼고, 준비용 목록 용량도 미리 확보한다. CPU 시각 갱신은 검증 PC에서 약 `0.003ms`, 관리 메모리 할당은 0으로 확인했다. **전체 FPS·GPU 시간·HMD 성능을 뜻하지 않는다.** 첫 표면 표본/캐시 준비 비용은 남아 있다.
- 거리 기준은 전환 시작 시 카메라 중심 위치로 고정한다. **160m 녹색 배경 지면은 구를 만들지 않고 원본 표면 디졸브만 적용**하며 스카이박스는 그대로다. 원본 활성 메시 9개는 복제 디졸브 재질 하나를 공유하고, 원본 메시·아틀라스·재질·텍스처 읽기 설정은 수정하지 않는다.
- 평면 패널 UI는 backing이 깨지기 전에 숨기고 나중에 복원한다. 전환/소멸 중 UI·물리 레이 선택만 차단하며 바닥 충돌·고정 HUD·기존 이동은 유지한다. 비활성화·Play 종료 시 메시·재질·음원 풀을 해제하고 원래 UI/충돌 상태를 복원한다.

### 반복되는 ‘뽁’ 효과음

- `Arts/Audio/TitleScene/BubblePop_Original.wav`: **48kHz·모노·150ms·16비트 PCM, 약 14KB**의 새 합성 음원이다. 미리 로드하여 이벤트마다 합성하거나 파일을 스트리밍하지 않는다.
- **현재 음원은 V2 수정본**이다. 사용자 청음 피드백 후, 초반 위상이 낮은 쪽에서 빠르게 올라가는 특성과 4ms 단위 음량 곡선을 다시 분석해 반영했다. 기존의 내려가는 주요 피치와 불필요한 배음/비정수 공명음을 제거하고 초반 8~10ms의 짧고 눌린 압력음을 강조했다. 새 위상/파형을 합성한 것이며 원음 샘플 복사는 아니다. 수치상 음량 곡선·초반 스펙트럼 차이는 줄었지만 최종 유사성은 사용자 청음으로 판단해야 한다.
- 레퍼런스 `https://www.youtube.com/watch?v=Ge2zHoXskC8`는 브라우저의 정상 재생 오디오를 Web Audio로 PCM 분석했다. 주된 5ms RMS 구간 약 60ms, 짧은 어택/감쇠, 1024샘플 Hann DFT의 주된 공명 빈 약 750~900Hz를 참고했다. 분석 수치·방법·한계는 `CodexTemp/LobbyPopFade~/reference-analysis.json`에 있다. **원본 샘플은 게임 음원에 복사하지 않았다.** 사람처럼 청음했다는 의미는 아니다.
- 사라짐·등장 모두 `0.08~0.15초`의 불규칙한 간격으로 반복한다. V2 음색 승인 후 재생 수만 늘리기 위해 이전 `0.10~0.19초`보다 약 25% 잦게 조정했다. 각 팝의 피치는 `0.88~1.18`, 기본 볼륨은 `0.28`로 유지하며 약간의 음량/좌우 변화도 준다. 인접한 소리가 비슷한 피치로 반복되지 않도록 조절한다. Inspector의 **Play Droplet Pops / Pop Volume / Pop Pitch Range / Pop Interval Range**로 조정한다.
- **6개 AudioSource를 한 런타임 오브젝트에 미리 준비**하고, 각 소리가 독립된 피치로 끝나도록 재사용한다. 정상 시험에서 2개가 겹쳐 재생됐다. 구마다 소스를 만들지 않으며, 큰 프레임 지연 후 놓친 소리를 몰아 재생하지 않는다. 풀에 빈 소스가 없으면 해당 이벤트를 생략한다. 기존 AudioListener·다른 사운드는 변경하지 않는다.
- VR에서도 고개 움직임에 따라 튀지 않도록 2D 소리로 재생한다. 대기 중에는 새 소리를 내지 않고, 끝점에 도달한 직전 팝의 짧은 꼬리만 자연스럽게 끝난다. 효과음 끄기·컴포넌트 비활성화·씬 종료 시 소유한 소리만 정지/해제한다. 클립이 없어도 시각 페이드는 계속 동작한다.

### 구현과 확인

- `Scripts/TitleScene/LobbyDissolveTest.cs`: 기존 K·진행·UI/충돌·자원 생명주기. `LobbyDropletRenderer.cs`: 표면/색상 표본과 고정 메시 소유. `LobbyDropletMesh.cs`: 구 템플릿. `LobbyDropletPopAudio.cs`: 제한된 음원 풀·피치/간격 변주.
- 셰이더는 `LobbyDropletToon.shader`, 원본 표면의 `TitleAtlasDissolve.shader`/`LobbyDissolveCommon.hlsl`, 공유 거리 진행 함수 `LobbyFadeCommon.hlsl`만 사용한다. URP·XR 스테레오/인스턴싱 경로를 유지했다. 불필요한 `LobbyMetaballMesher.cs`·메타볼 셰이더와 CPU 작업/취소 경로는 백업 후 제거했다. 이동한 자산의 기존 GUID는 유지했다.
- 최신 결과는 **`CodexTemp/LobbyPopFade~/`**다. Edit Mode 482항목, 구 형상 340항목, Play Mode 36항목을 검사했다. 승인된 저품질 캡처와의 차이는 사실상 없었고, 실시간 왕복·거리 순서·원복·피치 변화·겹침·Unity AudioSource의 실제 비영(非零) 출력·끝점 무음·해제 처리를 확인했다. `BubblePop_Fade_Preview.wav`는 기록된 실행 이벤트의 시각/피치/음량/좌우를 재구성한 청음용 파일이며 HMD 녹음은 아니다.
- 이전 `LobbyLowQualityFade~/`, `LobbyLightweightFade~/`, `LobbyMetaballUpdate~/`, `LobbyDissolveTest~/`는 과거 비교 기록이다. 해당 임시 도구는 제거된 API를 사용하므로 현재 버전에 그대로 실행하지 않는다. 현재 코드/씬은 임시 폴더에 의존하지 않는다. 다른 씬·스카이박스·공유 설정·패키지는 변경하지 않았다. **실제 물리 K 입력·주관적 청음·HMD 양안/성능/착용감·플레이어 빌드는 별도 확인 대상이다.**

## 이야기 씬 전환

엘리베이터 **체험 시작**에 **기존 물방울 페이드**를 연결했다. 로비가 2.5초 동안 사라지고, 원래 하늘 위에 월드 고정 상황 카드와 점 3개가 나타난다. 카드는 Lerp로 짧게 떠오르며 나타났다 내려가며 사라진다. 시점 회전과 HMD 추적은 유지하고 이동·선택만 막는다. 안내는 최소 1.5초이며, **도착한 엘리베이터도 같은 물방울 효과로 2.5초 동안 등장**한다. 로비 **F8**, 엘리베이터 **F9**은 약 6.5초의 왕복 미리보기다. 엘리베이터 단독 Play에도 시작 연출을 적용했다. 기존 K의 3초/3초, 구·팝 설정, 로비 배치와 준비 중인 두 체험은 유지한다. 자세한 조정 위치·검증·영상은 `Assets/M/Documentation/SceneTransition.md`를 참고한다.

임시 `VR_Preview_Test`는 현재 꺼 두어 HMD 없는 PC에서 일반 카메라·마우스 조작으로 시작한다. 실제 XR 리그와 미리보기 코드·패키지는 보존했다. 전환 중에도 원래 Lit 조명·그림자·유리 투명도와 거리 마스크 외곽선을 유지해 완료 순간 명암이 갑자기 바뀌지 않도록 수정했다. 추가 대기 시간은 넣지 않았다. 최신 PC 검사·영상은 **`CodexTemp/ShadowReadyPC~/`**, 이전 월드 패널/자유 시점 기록은 `CodexTemp/WorldTransitionLerp~/`다. 실제 HMD·플레이어 빌드·성능은 별도 확인 대상이다.
