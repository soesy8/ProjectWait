# VR 진입·컨트롤러·레터박스 정리 — 2026-11-13

- 목표 안내의 `!DialogueOnScreen()` 표시 정책은 **수정하지 않았다**.
- 임시 테스트 기능 정리(요청 5번)는 **보류**했다. `PC_Test_Controls`, 개발 패널/단축키, `VR_Preview_Test`, Mock HMD, `LobbyDissolveTest`와 관련 패키지·설정을 제거하거나 정식 기능으로 재분류하지 않았다.
- 기존 월드 고정 대화/선택지/관찰, 이야기 내용과 진행 코드는 유지했다. 기존 폰트 및 M 밖 XR 설정의 사용자 변경을 되돌리지 않았다.

## 스폰과 방향

- 기존 체육관 도입 위치 `(0, 7.92, -13)` 및 모든 층/이동 좌표를 유지했다.
- 저장된 Camera Offset Y를 `1.36144 → 0`, 카메라 로컬 Y를 `-0.2549641 → 1.1064756`으로 정리했다. XROrigin의 Floor 모드와 Device 눈높이 설정은 그대로다. 이 저장값은 유효한 추적 포즈를 대신하지 않는다.
- `ElevatorDesktopControls`가 초기 스폰 요청을 소유한다. 다음 프레임 이후 추적 모드, native Position/Rotation 추적 상태, 포즈 드라이버의 실제 반영 여부가 준비된 뒤 리그만 한 번 이동한다. 준비 전에는 진행/상호작용과 화면 공개를 대기한다.
- Floor 모드: 실제 바닥 기준의 추적 눈높이를 사용하고 원점을 목적지 바닥에 놓는다. Device 모드: 인계받은 눈높이(단독 시작 시 기존 기본 눈높이)를 사용하며 캡슐 발 위치를 다시 맞춘다.
- 단독 시작과 로비 진입 모두 목적지의 authored 정면으로 **yaw를 초기화**한다. VR의 실제 pitch/roll 및 카메라 로컬 추적 포즈는 건드리지 않는다. 이후 고개 움직임을 매 프레임 고정하지 않는다.
- PC 진입도 목적지 정면/수평 시점으로 초기화하되 기존처럼 인계 눈높이를 유지한다. 이후 마우스 시점, 이동, 컷씬 진행은 유지한다.
- 씬 전환은 카메라의 미초기화 저장 포즈 대신 목적지 발 위치를 사용하고, 도착 처리가 준비됐다는 반환값을 받은 뒤 공개한다.

## 로비 컨트롤러

- `Assets/M/Prefabs/Controllers/LeftAimController.prefab`, `RightAimController.prefab`을 추가했다. 엘리베이터의 12개 오브젝트/9개 메시, 재질 참조와 로컬 변환을 그대로 재사용하는 시각 전용 프리팹이다. 새 GUID를 부여했다.
- 모델의 Z `−0.05m`, Y `180°`, 오른손 X 반전, 내부 모델 축 보정을 보존했다. 샘플 입력 동작/콜라이더는 시각 프리팹에 넣지 않았다. 엘리베이터 원본은 수정하지 않았다.
- 로비 모델과 선택 레이가 같은 OpenXR Aim 포즈를 사용한다. Grip 포즈에 Aim용 모델을 붙이던 기준 차이를 제거했다. 선택 레이에 임의의 각도 보정을 적용하지 않았다.
- 포즈 검사 코드를 공통화했다. 실제 제공자의 byte-1 (`1/255`) 추적 플래그, Position/Rotation 상태, 유한값 검사, 추적 끊김 시 숨김 및 복구 후 트리거 재입력 정책을 유지했다.

## VR 레터박스와 제한적 최적화

- 하단만 `246/720`이던 구성을 **상·하단 각각 `123/720`**으로 변경했다. 두 배경의 실제 높이도 동일하다. 기울어진/비대칭 눈 투영에서 필요한 초과 배경은 화면 바깥으로 확장한다.
- 기준 높이는 각 눈의 중앙 native 시야 높이로 계산한다. 기울어진 frustum의 큰 bounding box를 기준으로 얇은 띠를 계산할 때 발생하던 자막 여백 부족을 방지한다.
- 자막은 하단 띠 안에서 더 넓게 재배치한다. 글자 크기는 줄이지 않는다. 실제 글자/배경의 네 모서리를 양쪽 눈에서 검사하고 슬라이드 중 공간이 부족하면 잠시 숨긴다.
- 얇은 띠이므로 종전 `−28°` 선호 위치를 강제할 수 없다. 검증 투영에서 자막 중심 최저 고도는 약 `−41.54°`였다. 실제 렌즈 가독성·편안함은 기기에서 확인해야 한다.
- PC의 기존 상·하단 `82/720`, 자막 및 전체 암전은 유지했다.
- 같은 텍스트/폰트/폭의 TMP 크기 측정을 재사용한다. 같은 양안-평면 상대 변환에서는 계산된 로컬 기하를 재사용하고, 투영/IPD/클리핑/평면 크기 변경 시 무효화한다. 월드 위치·시선 판정은 캐시하지 않는다.
- 최적화에 대한 FPS 상승을 주장하지 않는다. 미변경 자막 60회 배치에서 추가 TMP 측정이 없다는 것은 하네스로 확인했다.
